# ขั้นสร้าง (ทำหลังผู้ใช้ยืนยันสรุปแล้วเท่านั้น)

## 1) กระดานงานใน Notion
โหลดเครื่องมือ Notion ด้วย ToolSearch (`notion-create-database`, `notion-create-pages`, `notion-update-page`, `notion-query-data-sources`, `notion-fetch`) สร้างฐานข้อมูลส่วนตัวระดับ workspace (ไม่ใส่ parent ถ้าผู้ใช้ไม่ได้ระบุที่) ใช้ schema นี้ แล้วปรับชื่อสถานะและทีมให้ตรงกับวงจรงานที่ยืนยันแล้ว:

```sql
CREATE TABLE ("งาน" TITLE,
 "สถานะ" STATUS('คิวรอ':gray:to_do, '<ขั้น 1>':blue:in_progress, ... , '<ขั้นอนุมัติ>':orange:in_progress, ... , 'โพสต์แล้ว/เสร็จแล้ว':green:complete, 'ติดปัญหา':red:in_progress),
 "ทีม" SELECT('<ห้อง 1>':green, ...),
 "ความคืบหน้า" NUMBER FORMAT 'percent',
 "คุณอนุมัติแล้ว" CHECKBOX COMMENT 'ด่านอนุมัติ: เจ้าของติ๊กเองเท่านั้น ห้ามทีมติ๊ก ห้ามเริ่มขั้นที่ใช้เครดิต/ส่งออกก่อนติ๊ก',
 "ตัวต่อที่ใช้" MULTI_SELECT('Notion':default, ...),
 "ลิงก์ผลงาน" URL, "นัดโพสต์" DATE, "ผู้รับผิดชอบ (บทบาท)" RICH_TEXT, "โน้ตทีม" RICH_TEXT, "แก้ไขล่าสุด" LAST_EDITED_TIME)
```
จดค่า data source id จากผลลัพธ์ (`collection://...`) ไว้ใช้ในแดชบอร์ด ชื่อคอลัมน์ในแดชบอร์ดต้องตรงตัวกับ schema ถ้าเปลี่ยนชื่อ ต้องแก้ทั้งสองที่

## 2) ปรับแม่แบบแดชบอร์ด
คัดลอก `assets/office-dashboard.html` เป็นไฟล์ทำงานของผู้ใช้ แล้วแก้ตัวแปรเหล่านี้ให้สอดคล้องกัน (เปลี่ยนอย่างเดียวแล้วอีกที่ไม่ตามจะพัง):

| ตัวแปร | อยู่ใน | หน้าที่ |
|---|---|---|
| `DS`, `DS_ID` | สคริปต์แดชบอร์ด | data source ของกระดานงาน (ต้องเป็นของผู้ใช้ ไม่ใช่ค่าเดิมในแม่แบบ) |
| `ZONES` | สคริปต์ฉาก | ห้อง/จุดบนเกาะ: ตำแหน่ง ชื่อ รายชื่อบทบาท สีหลังคา |
| `CAST` | สคริปต์ฉาก | ตัวคนในแต่ละห้อง (สีเสื้อ ทรงผม) |
| `TICKETS` | สคริปต์ฉาก | ตั๋วสถานะที่ปักบนเกาะ (คำ ตำแหน่ง) |
| `EDGES` | สคริปต์ฉาก | เส้นด้ายแดงของแต่ละขั้น (ป้ายคำ จุดผ่าน) |
| `STEPS` | สคริปต์ฉาก | ขั้นตอนของวงจรงาน: ชื่อ คำอธิบาย ห้องที่เกี่ยวข้อง ขั้นอนุมัติ |
| `STATUS_STEP`, `STEP_LABEL`, `ZONE_OF_STATUS`, `TEAM_ZONE`, `ZONE_TEAM`, `ACTIVITY`, `TEAMS`, `CONNECTORS` | สคริปต์แดชบอร์ด | แมปสถานะใน Notion ไปยังขั้น ห้อง และข้อความ "ตอนนี้ใครทำอะไร" |
| `HIT` | สคริปต์แดชบอร์ด | พื้นที่คลิกบนเกาะ (ตามตำแหน่งใน `ZONES`) |
| ชื่อหัวเรื่องและบรรทัดรองบนภาพ | ฟังก์ชัน `buildStatic` | ชื่อออฟฟิศของผู้ใช้ |
| `<title>` และ `<h1>` | ส่วนหัวหน้า | ชื่อหน้า (2 ถึง 4 คำ) |

ข้อควรจำ:
- แม่แบบมี 6 ห้อง 8 ขั้น ถ้าวงจรของผู้ใช้ต่างจากนี้ ให้ปรับ `STEPS`, `EDGES`, `TICKETS`, `STATUS_STEP`, `STEP_LABEL` พร้อมกัน และถ้าจำนวนห้องต่าง ให้ปรับ `ZONES`, `CAST`, `HIT`, `HK`, รายการห้องใน `staticItems`
- เปลี่ยนห้องหรือขั้นจนภาพทับกันได้ ต้องเรนเดอร์ดูทุกครั้ง
- ห้ามเขียนข้อความอธิบายวิธีสร้าง ที่มาของโค้ด หรือสถานะการตรวจสอบภายในไว้ท้ายหน้า หน้านี้เป็นหน้าใช้งานของผู้ใช้
- ตัวเลขหรือข้อความที่ใส่บนหน้าต้องมาจากสิ่งที่ผู้ใช้ให้มา ห้ามแต่งตัวอย่างที่ดูเหมือนข้อมูลจริง

## 3) ทดสอบก่อนเผยแพร่
- มี Chromium และ Playwright ติดตั้งในสภาพแวดล้อมคลาวด์อยู่แล้ว ถ้ามี ให้เปิดไฟล์ ถ่ายภาพ และดูด้วยตา ตรวจว่าอักษรไทยไม่แตก ป้ายไม่ทับกัน ไม่มี error ในคอนโซล ไม่มีการเลื่อนแนวนอนที่ 390px
- หน้านี้เรียก `window.claude` ซึ่งไม่มีนอก claude.ai จึงทดสอบตรรกะปุ่มด้วยตัวจำลองที่ฉีดผ่าน `addInitScript` (จำลอง `use('mcp')`, `use('db')`, `use('user')` และผลลัพธ์ของ query) ตัวจำลองยืนยันแค่ตรรกะหน้า ไม่ใช่การเชื่อม Notion จริง ต้องบอกผู้ใช้ตามนั้น
- ข้อความ "null" หลุดบนหน้า: ระวัง `append(null)` ใช้ตัวช่วยที่กรองค่าว่าง

## 4) เผยแพร่
- โหลดสกิล artifact-capabilities ก่อนประกาศสิทธิ์
- ประกาศเฉพาะที่ใช้: `mcp` กับ Notion (`notion-query-data-sources`, `notion-update-page`, `notion-create-pages`), `db` กับกฎ `approvals` อ่านได้ทุกคนที่เปิดหน้า เขียนได้เฉพาะเจ้าของ, และ `user` ใช้ตรวจว่าใครคือเจ้าของ
- เผยแพร่เป็น Artifact ส่วนตัว บอกผู้ใช้ว่าเปิดได้เฉพาะเขา ถ้าจะแชร์ต้องแชร์เองที่เมนู Share
- ตรวจหลังเผยแพร่หนึ่งรอบ: อ่านคอลเลกชันที่หน้าเขียน และอ่านที่ระดับสิทธิ์ต่ำว่าต้องไม่เห็นสิ่งที่ซ่อน แล้วรายงานสิ่งที่ตรวจได้และตรวจไม่ได้
- เขียนลง Notion จริงเฉพาะเมื่อผู้ใช้สั่งให้ลองเอง การทดสอบเขียนด้วยตัวเองจะเปลี่ยนงานจริงของเขา

## 5) ตั้งต้นงานแรก (ถ้าผู้ใช้ให้หัวข้อ)
สร้างแถวงานแรกในกระดาน แล้วให้ทีมแรกทำจริงเป็นร่าง บันทึกผลลงหน้างาน ตั้งสถานะให้ตรงกับเนื้อหาที่เขียนเสร็จ (เขียนเนื้อหาก่อน แล้วค่อยเปลี่ยนสถานะ ไม่ใช่ทางกลับกัน) แล้วหยุดที่ด่านอนุมัติรอเจ้าของ อ้างแหล่งข้อมูลที่ค้นมาและบอกข้อจำกัด (เช่น แหล่งที่เป็นบล็อกผู้ขายเครื่องมือ กติกาแพลตฟอร์มที่ยังไม่ได้ค้น)

## 6) หลังส่งมอบ
หน้าแดชบอร์ดแจ้งผู้ช่วยเองไม่ได้ ให้ผู้ใช้พิมพ์บอกในแชตหลังกดอนุมัติหรือสั่งงานใหม่ ผู้ช่วยจะอ่านสถานะจาก Notion แล้วให้ทีมถัดไปทำต่อ ถ้ามีเรื่องที่ผู้ช่วยไม่แน่ใจว่ากระดานตรงกับความจริงไหม ให้อ่านกระดานซ้ำก่อนทำ
